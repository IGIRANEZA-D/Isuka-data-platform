# Landing Page Build Decisions

## Pre-flight

- Public root is explicitly routed by `backend/src/server.js` to `www/landing.html`; `/dashboard/` is served separately from `frontend/index.html`. The existing lower-page story, anchors, and overview widget are in `www/landing.html`; preserve that live landing page and its existing downstream sections.
- The public landing includes `explore`, `districts`, and `method` anchors and a live overview widget. Keep those downstream sections and calculations intact while adding the requested screens.
- Existing brand assets include `www/isuka-logo.png` and `www/Logo in white.png`. `www/farmer-silhouette.png` exists. The requested `www/landing-reference.png` does not exist. No local district GeoJSON or local font files were found. To honor the no-CDN rule, the new page will not request Google Fonts; it will declare Baloo 2 / Work Sans first with local system fallbacks.
- District Explorer currently obtains geometry through `/api/rwanda-districts`, whose FeatureServer GeoJSON exposes `code_dist`, `district`, and `name`; the endpoint returned 30 district polygons. District Explorer matches by district name and does not parse a district query parameter, so map links will open `/dashboard/district-explorer/` without adding a nonfunctional query.
- Existing verified data paths: `/api/overview?year=...&district=...&season=...` returns national production-weighted loss, `dataQuality.rowsRead`, and district loss percentages using the shared overview aggregation; `/api/climate-risk?year=...` returns the same all-season district loss aggregation. `/api/loss-planner/baseline?years=2025&seasons=all` returned confirmed kilogram stage fields for A/B/C. Its own metadata reports coverage and rows excluded when stage components exceed reported totals.
- No root `build:data`, `check:all`, `baseline/api-hashes.json`, or API hash guard was found. `frontend/dist` exists; no `data/dist` folder exists. Existing test/build scripts are root `npm test`, `npm run verify:data`, and frontend `npm --prefix frontend run build`.
- Existing hardcoded public statistic to retain and report: the lower Impact section's `70%` workforce claim. The old hero's `30 / 5 / 1` pseudo-counter labels are being replaced by API metadata, not presented as verified observations. No testimonial was found.

## Conservative Implementation Decisions

- Add only `GET /api/landing/summary`; leave all existing API response bodies and calculations unchanged. Assemble national and district values by calling existing `getOverview`/shared aggregation for the 28 year/season combinations, including `all-years`, then map names to `code_dist` using the generated local geography artifact.
- Build deterministic art from the existing Rwanda boundary service output and commit the compact outputs. Runtime landing requests will use local committed art, never a third-party map request. A stable seeded noise function, deterministic simplification, polylabel-style interior-point search, and Hungarian assignment with validation will be used.
- Journey-stage units are confirmed for 2025 A/B/C and baseline weighted production matches Overview within floating-point tolerance, but the verified baseline reports 2,206 invalid-loss rows and 80 negative-loss rows (all seasons, 2025). Omit stage percentages rather than imply complete stage attribution; use the required illustrative caption.
- Preserve existing downstream sections and their logic, preserve `/dashboard/`, `/account/login`, and `/account/signup`, and retain any pre-existing hardcoded statistic as noted above.

- Terrain and district art may total up to 110 KB compressed when delivered as a deferred, cached static asset; keep the hero copy in initial HTML. Reduce contour levels to 16 and coordinate precision before considering any further size relaxation. The build now uses 16 contour levels and a 120 by 76 contour grid to keep terrain below 30 KB gzip. The GIS boundary service returned 502 from this environment, so no art output has been generated yet.

## Ask Isuka Pre-flight and Conservative Decisions (2026-10-24)

- Reused `buildDetailedTimeSeries(getAllPeriods())`, which is produced from the existing Overview aggregate calculations. Ask Isuka converts weighted kg to tonnes and uses the existing weighted hectares; it does not read or return respondent rows. `AGGREGATE_CALC_VERSION` is `loss-label-resolver-v1-crop-labels-v1-production-aliases-v1`.
- Crop codes come from the canonical `crop-name-map.js` normalization as present in the aggregate artifacts; district codes are normalized lowercase names. Available configured survey periods are 2020–2025, seasons A/B/C. Existing account assistant image is `www/ISUKA BOT.png`, served by `/assets/ISUKA%20BOT.png`; account assistant pages and endpoints were not changed.
- Dashboard CSS tokens use `--primary`, `--accent`, `--bg`, `--text`, `--text-muted`, and `--border`. Existing tests run with `npm test`; `npm run verify:data` exists. No API hash baseline was present, so existing endpoint handlers/calculations were left untouched.
- New request code suppresses cells with fewer than 30 aggregate records. Citation is generated from selected periods and calculation version. Unknown schema values are rejected. The deterministic parser is always available; an optional structured LLM adapter is implemented, but no provider is configured. Draft Kinyarwanda aliases are explicitly flagged for teammate review.
- Additive UI is wired only into the eight requested dashboard pages. It uses one shared stylesheet and a small idle loader; the drawer app is requested only on first open. The landing, account, and admin pages are untouched.
